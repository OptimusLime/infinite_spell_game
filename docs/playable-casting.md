# Playable casting study

The game project consumes the reusable engine `spell-player` package. The game owns `players/casting-study.player.toml`, two authored YAML definitions under `spells/casting-study/`, and four scene documents under `scenes/casting-study-*`. The controls, generic Inventory, separate Equipment, finite cartridge funding, authored revision admission and physical execution remain in shared Rust components.

This is a provisional integration study, not accepted art, balance or the complete game. The actor, targets, projectile shapes, capacities, grid sizes, costs and camera values are explicit test inputs inherited from the engineering proof. The four cel/pixel day/night documents share one canonical configuration and session; they are comparison views, not an approved in-game look-switch mechanic. The fixed actor uses explicit named aim targets. Walking, mouse-ground aiming, world generation and final visual design are separate work.

Run `./scripts/play` from the game checkout. The command uses the engine CLI (override its location with `ATELICO_APP`), opens the `casting-study` form and enables play. It reuses an existing game host and preserves its inventory. A new host starts a fresh process-local study. Alternatively, open `scenes/casting-study-cel-day.scene.luau` in the editor and enable Play. Equip the wand, load amber, select the directed bolt study, choose the front target, then Fire. The configured keys are shown beside the controls. Selection and aiming spend nothing. The bottom total includes each owned physical cartridge once; the loaded source is also shown separately. Depleted sources refuse a cast and can be replaced from Inventory.

To revise a spell, open `spells/casting-study/bolt.spell.yaml` in the native editor. Choose **Details**, edit a field, scroll to **Apply details**, then **Save**. Return to the casting-study form, open **Authored sources**, preview that spell ID, then explicitly **Admit this revision**. The saved draft alone does not change the Player. A changed file after preview must be previewed again. Admission changes future casts without refilling the inventory or resetting Equipment, physical bodies or funded receipts. Current scenes and camera views share that finite session. Configuration edits require an explicit new session identity; host restart does not restore a durable full-world save.

The ordinary engine package installer records exact package versions and hashes in `atelico.lock`. Native code is built against this checkout's engine, as required by the current registry workspace contract. Installed legacy Spellcraft examples are dependency samples; this study references only the game-owned definitions named in its player configuration.
